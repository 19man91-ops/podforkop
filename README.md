# PodForCOP

**PodForCOP** — это форк [Podkop](https://github.com/itdoginfo/podkop) для OpenWrt с интеграцией расширенного ядра [sing-box-forkop](https://github.com/ushan0v/sing-box-forkop). Проект создан для удобной, точечной маршрутизации трафика через VPN и прокси с поддержкой любых форматов подписок, современных протоколов, интерактивного управления секциями и мониторинга в реальном времени.

Направляйте нужные ресурсы в туннель, а остальной трафик — напрямую без потери скорости.

## 🆕 Что нового в 0.9.3

* **Честное определение возможностей ядра.** Для `sing-box-forkop` больше не объявляются неподдерживаемые возможности (`urltest.fallbacks`, `urltest.download_url`, uTLS fallback): настройки, которые ядро не умеет, скрыты в интерфейсе и пропускаются при генерации конфига. Раньше их включение давало невалидный конфиг и Podkop не запускался.
* **Совместимость с альтернативными ядрами.** Убрано добавление `"providers": []` для `podkop-engine` и stock sing-box; при нескольких DNS-серверах на ядре без поддержки DNS-fallback используется первый сервер с предупреждением в логе (а не падение конфига).
* **Кэш подписок при старте.** Для forkop включён `cache_file.store_subscriptions` — провайдеры подписок поднимаются из кэша, даже если сервер подписки недоступен при загрузке.
* **Безопасность установщика.** Убрана опция `--no-check-certificate`: TLS проверяется всегда. `SHA256SUMS` обязателен, суммы проверяются для всех трёх пакетов, установка прерывается при любой ошибке.
* **Автозапуск.** Установщик включает автозапуск службы (`/etc/init.d/podkop enable`), поэтому Podkop переживает перезагрузку.
* **Безопасный `update-fast.sh`.** Все файлы скачиваются в staging-каталог, заменяются только после успешной загрузки всего набора, библиотеки кладутся в правильный каталог `/usr/lib/podkop/`, добавлены `monitoring.js`, `dashboard.js`, `diagnostic.js` и все backend-библиотеки. Версия берётся из установленного пакета (тег), а не из `main`.
* **Один рестарт на Save & Apply.** Убран дублирующий procd reload-trigger: служба перезапускается ровно один раз из обработчика LuCI.
* **Drag & Drop.** При наличии штатного LuCI sortable (OpenWrt 24.10+) используется он; собственная реализация остаётся только для старых LuCI. Двойные обработчики, ломавшие перетаскивание, убраны.
* **Исправления интерфейса:** кнопка «Закрыть все» в мониторинге снова работает на shell-fallback; исправлено отображение URL-подписок на дашборде; добавлены недостающие русские переводы.
* **Monitroing/типы/CI:** исправлены ошибки TypeScript, добавлены проверки `tsc` и `prettier` в CI.
* **Секреты:** `link` parser-outbound и провайдеры маскируются в диагностическом выводе конфига.

## 🚀 Ключевые возможности

### 1. 🔄 Перетаскивание секций и наглядный статус
* Управление приоритетом правил маршрутизации перетаскиванием строк таблицы секций (сверху вниз — первое совпадение побеждает). Порядок сохраняется в UCI.
* В LuCI с поддержкой sortable (OpenWrt 24.10+) используется штатная ручка перетаскивания LuCI; для старых версий — перетаскивание строки.
* **Наглядный бейдж режима** в таблице секций:
  * 🔵 **Proxy** (Subscription, URL, Selector, URLTest)
  * 🟢 **VPN** (WireGuard, AmneziaWG, OpenVPN)
  * 🔴 **Block** (блокировка трафика)
  * 🟣 **Exclusion** (исключение из маршрутизации)
* Быстрый чекбокс **«✔ Включено»** для отключения/включения секции без удаления её настроек.

### 2. ⚡ Автоматический запуск при сохранении
* При нажатии **«Save & Apply»** служба перезапускается один раз и начинает маршрутизацию с новыми параметрами.
* Установщик включает автозапуск Podkop при загрузке роутера; кнопка **«Enable autostart»** в «Диагностике» позволяет управлять этим вручную.
* Ошибки применения изменений показываются в интерфейсе, модальное окно не «зависает».

### 3. 🌐 Подписки всех форматов
* Поддержка ссылок на подписки любого VPN-провайдера (HTTP/HTTPS) или локальных файлов со списком узлов на роутере (например, `/etc/podkop/servers.txt`).
* **Все основные форматы «из коробки»**: Base64, конфигурации **Clash** и **Mihomo YAML**, **sing-box JSON**, **Xray JSON**, профили **SIP008**, списки прямых ссылок.
* Подписки можно использовать как отдельный тип подключения (**Subscription**), в группе **Selector** (ручное переключение на Дашборде) и в группе **URLTest** (автоматический выбор по задержке).
* Автоматическое обновление подписок по расписанию и вручную по кнопке или команде `/usr/bin/podkop subscription_update`.
* Для forkop подписки сохраняются в кэш ядра и доступны после перезагрузки даже при недоступности сервера подписки.

### 4. 🛡️ Поддержка современных протоколов
* **VLESS** (включая Reality, XTLS Vision, XHTTP, gRPC);
* **Trojan**;
* **Shadowsocks** (включая Shadowsocks 2022);
* **Hysteria 2** (`hysteria2://`, `hy2://`);
* **TUIC**;
* **AnyTLS**, **VMess**, **SOCKS5**, **HTTP(S)**;
* **NaiveProxy** (в сборке ядра `full`).

### 5. 🎯 Точечная маршрутизация по правилам и секциям
* **Списки сообщества**: готовые наборы правил (YouTube, Discord, Telegram, Instagram, Meta, Twitter, AI-сервисы, антиблокировочные списки РКН и GeoIP).
* **Пользовательские списки**: домены, IP-адреса, CIDR-подсети, локальные текстовые файлы и наборы правил `.srs`.
* **Маршрутизация клиентов (`fully_routed_ips`)**: перенаправление всего трафика выбранных устройств через туннель.
* **Действия над трафиком**: `Proxy`, `VPN`, `Bypass` (напрямую) и `Block`.

### 6. 📊 Дашборд и вкладка «Мониторинг» соединений
* **Дашборд**: активные узлы подписок, проверка пинга в один клик, ручное переключение серверов, флаги стран.
* **Вкладка «Мониторинг»**:
  * список активных TCP/UDP соединений клиентов сети в реальном времени;
  * имена клиентов по DHCP/ARP/статическим записям;
  * назначение соединения: протокол, домен/IP, порт, секция и исходящий узел;
  * объём трафика (Upload/Download) и длительность сессии;
  * закрытие одного соединения или всех, фильтрация по устройствам/хостам;
  * адаптивный polling, пауза при скрытой вкладке.

### 7. 📥 Прямой маршрут для BitTorrent
* Опция **«Bypass sections for BitTorrent traffic»** позволяет пускать P2P-трафик торрентов напрямую в обход VPN.

### 8. 🌐 Несколько DNS-серверов (DNS failover, только forkop)
* Несколько основных и bootstrap DNS-серверов со стратегиями `sequential` (по очереди) и `parallel` (самый быстрый ответ).
* Поддерживается только ядром `sing-box-forkop`; при альтернативном ядре (`PODFORCOP_CORE=podkop-engine` или stock sing-box) используется первый сервер, а в лог пишется предупреждение.

## 📦 Установка и обновление

Установщик полностью автоматизирован, не зависит от лимитов GitHub API, проверяет TLS и SHA256-суммы пакетов, корректно заменяет старые ядра и **включает автозапуск службы**.

Поддерживаются:
* OpenWrt **24.10** с пакетным менеджером `opkg` (ipk);
* OpenWrt **25.12+** с пакетным менеджером `apk` (apk).

### Стандартная установка (рекомендуется):

```sh
sh <(wget -O - https://raw.githubusercontent.com/19man91-ops/podforkop/main/install.sh)
```

По умолчанию устанавливается сборка ядра `base` (VLESS, Trojan, Shadowsocks-2022, Hysteria 2, TUIC, AnyTLS, VMess, SOCKS).

### Установка с максимальным набором протоколов (`full`):

```sh
PODFORCOP_FORKOP_VARIANT=full sh <(wget -O - https://raw.githubusercontent.com/19man91-ops/podforkop/main/install.sh)
```

### Установка с альтернативным ядром (`podkop-engine`)

```sh
PODFORCOP_CORE=podkop-engine sh <(wget -O - https://raw.githubusercontent.com/19man91-ops/podforkop/main/install.sh)
```

> Альтернативное ядро не поддерживает DNS-failback, `providers`-подписки и часть новых возможностей forkop. Для полного набора функций используйте forkop (по умолчанию).

### Быстрое обновление UI и backend-скриптов без переустановки пакетов

```sh
wget -qO- https://raw.githubusercontent.com/19man91-ops/podforkop/main/update-fast.sh | sh
```

Скрипт скачивает набор файлов в staging-каталог, проверяет, что все загрузки успешны, затем атомарно применяет их и перезапускает службы. Версия источников берётся из установленного Podkop (git-тег), поэтому смешивания версий не происходит. Для полноценного обновления (включая ядро и пакеты) используйте `install.sh`.

## 🛠️ Системные требования

* **OpenWrt 24.10, 25.12 или новее** (поддерживаются популярные архитектуры: `aarch64_cortex-a53`, `x86_64`, `mipsel`, `mips` и др.).
* Свободное место во flash-памяти: от ~45 МиБ для сборки `base` (установщик учитывает место, освобождаемое при замене старого ядра).
* Роутеры с 16 МБ Flash без внешнего накопителя (extroot) не поддерживаются из-за размера современных Go-ядер.
* Если был установлен `Getdomains`, удалите его перед установкой во избежание конфликтов таблиц nftables.

## 📖 Быстрый старт

1. Откройте панель управления LuCI: `http://192.168.1.1` ➔ **Службы** ➔ **Podkop** *(нажмите `Ctrl + F5` для обновления кэша интерфейса)*.
2. **Добавление подписки**:
   - Перейдите на вкладку **Секции** (Sections).
   - Нажмите **Редактировать** (Edit) у секции `main` (или создайте новую секцию).
   - В поле **Тип подключения** выберите `Proxy`.
   - В поле **Тип конфигурации** выберите `Подписка` (Subscription).
   - Вставьте URL подписки (например, `https://your-domain.org:2096/...`) или путь к файлу `/etc/podkop/servers.txt`.
   - В блоке **Списки сообщества** выберите нужные сервисы или укажите свои домены.
   - Нажмите **Сохранить** (Save) в модальном окне.
3. **Приоритет правил**:
   - На вкладке «Секции» перетащите нужную секцию выше или ниже (в LuCI 24.10+ — за ручку, в старом LuCI — за строку).
4. **Применение**:
   - Нажмите **Save & Apply** внизу страницы. Служба автоматически перезапустится с новой конфигурацией.
5. **Проверка**:
   - Откройте вкладку **Дашборд** (Dashboard), чтобы увидеть активные ноды, замерить пинг и выбрать оптимальный сервер.

## 🔍 Управление и диагностика в консоли

```sh
# Проверка версии ядра и активной сборки
sing-box version

# Проверка статуса службы
podkop get_status

# Управление автозапуском
podkop enable
podkop disable

# Принудительное обновление подписок
podkop subscription_update

# Просмотр логов работы службы
logread -e podkop
```
