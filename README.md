# PodForCOP

Форк [Podkop](https://github.com/itdoginfo/podkop) для маршрутизации трафика в OpenWrt с подписками на прокси и обходом секций для BitTorrent.

Направляйте нужные ресурсы в туннель, а остальное — напрямую. Открытое программное обеспечение на базе [sing-box](https://github.com/SagerNet/sing-box).

> [!WARNING]
> Проект находится в стадии бета-версии. Возможны ошибки, нестабильная работа и существенные изменения функциональности.

# Вещи, которые необходимо знать перед установкой

### Обновления и конфигурация
- При обновлении **обязательно** [очищайте кэш LuCI](https://podkop.net/docs/clear-browser-cache/).
- После обновления проверяйте конфигурацию — она может изменяться между версиями.
- При старте Podkop модифицируется конфигурация Dnsmasq.
- Podkop изменяет конфигурацию sing-box. Если вы используете собственную конфигурацию, заранее сохраните её.

### Системные требования
- Требуется OpenWrt 24.10 или выше.
- Необходимо минимум 25 МБ свободного места на устройстве. Устройства с флеш-памятью 16 МБ не поддерживаются.

### Важные ограничения и особенности
- Если установлен Getdomains, его [необходимо удалить](https://github.com/itdoginfo/domain-routing-openwrt?tab=readme-ov-file#скрипт-для-удаления)
- Dashboard доступен только при подключении по HTTP (из-за особенностей Clash API). При использовании HTTPS или домена работа может быть недоступна.

### Подписки на прокси

В секциях **Selector** и **URLTest** можно использовать прямые ссылки на прокси, HTTP(S)-ссылки на подписки или оба источника сразу. Для каждого типа достаточно заполнить хотя бы один список; если заполнены оба, ссылки объединяются. Подписки поддерживают обычный список ссылок и Base64-список. Ссылки передаются `podkop-engine` на разбор; поддерживаются VLESS, Trojan, Shadowsocks, SOCKS, Hysteria2, TUIC и HTTP(S). VMess, Hysteria, AnyTLS и NaiveProxy доступны с вариантом `podkop-engine-full`. Если в подписке есть неподдерживаемая ссылка, она пропускается с предупреждением в журнале; секция запустится при наличии хотя бы одной рабочей ссылки. Интервал обновления задаётся общей настройкой **List and Subscription Update Frequency**. Если загрузка не удалась, текущий кэш подписки не перезаписывается.

### Прямой маршрут для BitTorrent

В общих настройках включите **Bypass sections for BitTorrent traffic**, чтобы распознанные BitTorrent-соединения между узлами и DHT шли напрямую до применения правил секций. HTTP(S)-запросы к трекерам не распознаются как P2P-соединения.

### Поддержка и диагностика
- [Руководство по диагностике](https://podkop.net/docs/diagnostics/)

# Установка PodForCOP
Полное руководство доступно в [документации](https://podkop.net/docs/install/)

Для установки и обновления достаточно выполнить один скрипт:
```
sh <(wget -O - https://raw.githubusercontent.com/19man91-ops/podforkop/main/install.sh)
```

Установщик берёт пакеты PodForCOP и подходящий для архитектуры роутера пакет `podkop-engine` из релизов этого репозитория. Предварительная сборка `podkop-engine-current` содержит зеркала `.ipk` и `.apk` для поддерживаемых архитектур; workflow обновляет их из [официального репозитория podkop-engine](https://github.com/podkop-net/podkop-engine) и проверяет SHA256. При установке роутеру не нужно отдельно скачивать ядро из другого репозитория. Для Hysteria2, TUIC и остальных поддерживаемых URI PodForCOP использует `sing-box tools decode-link` из `podkop-engine`. Исходный код ядра и лицензия указаны в описании зеркального релиза. Если установлен `podkop-engine-full`, установщик обновляет именно этот вариант.

По умолчанию ставится компактный `podkop-engine`, которого достаточно для VLESS, Trojan, Shadowsocks, SOCKS, Hysteria2, TUIC и HTTP(S). Если в подписке есть VMess, Hysteria, AnyTLS или NaiveProxy, можно поставить расширенный вариант из того же зеркала:
```
PODFORCOP_ENGINE_VARIANT=full sh <(wget -O - https://raw.githubusercontent.com/19man91-ops/podforkop/main/install.sh)
```
