# Changelog

## 0.9.21

### Исправлено
- **Диагностика больше не зависает на «DNS проверки».** Раньше при зависшем shell/DNS-вызове проверка оставалась в состоянии `loading` навсегда, а следующие проверки не запускались.
- Каждая проверка диагностики теперь ограничена **20 секундами**; при таймауте или ошибке показывается «Не удалось получить результат», а остальные проверки продолжают выполняться.
- В backend DNS-проверок каждый `dig` ограничен 5 секундами через `timeout`, чтобы один недоступный DNS-сервер не блокировал весь вызов.
- Диагностика не менялась в 0.9.18–0.9.20 (0.9.18 — MAC/вендор в мониторинге, 0.9.19–0.9.20 — провайдеры задержки/скорости); это отдельное исправление устойчивости.

## 0.9.20

- Обновлены переводы.

## 0.9.18

### Мониторинг устройств
- В фильтре устройств теперь показываются **MAC-адрес и вендор**:
  - известное устройство: `Имя · IP · Вендор`;
  - устройство без DHCP-имени: `IP · MAC · Вендор` (например, `192.168.1.209 · 84:B4:D2:C0:39:74 · Shenzhen iComm Semiconductor`);
  - рандомизированные MAC помечаются как `Приватный MAC`.
- Поиск по Мониторингу учитывает MAC и вендора; полный MAC показывается в подсказке к пункту фильтра.
- Подписи по-прежнему берутся из DHCP/host hints, поэтому имя можно задать через статическую аренду в LuCI.

### Подписки
- `auto-fastest` (leastPing) в JSON-подписке теперь стоит **первым** в списке профилей; роутеру по-прежнему выдаётся raw-подписка без авто-выбора.

## 0.9.17

### Исправлено
- **Стабильный хэш применённой конфигурации:** в маркер и сравнение больше не попадает служебный
  флаг `shutdown_correctly`, который Podkop меняет при старте/стопе. Раньше из-за него статус мог
  «мигать» (`stale: true` после успешного применения). Теперь хэш считается по `uci show podkop`
  без этого флага, поэтому Save & Apply и проверка в UI завершаются стабильно.

## 0.9.16

### Исправлено
- **Hotfix `get_config_status`:** незаполненные переменные `uci_mtime`/`config_mtime` передавались в `jq --argjson`
  и вызывали ошибку «invalid JSON text passed to --argjson». Переменные инициализируются нулями,
  проверка по SHA256 работает корректно.
- **Проверено end-to-end на роутере:** изменение UCI → `stale: true`; `/sbin/reload_config`
  (путь LuCI Save & Apply) → Podkop перезапускается, конфиг применяется, `stale: false`;
  возврат настройки — снова `stale: false`. Серверный триггер работает без участия браузера.

## 0.9.15

### Исправлено
- **Надёжная проверка применения конфига по хэшу.** `get_config_status` теперь сравнивает SHA256
  `/etc/config/podkop` с состоянием, записанным после успешного `start`/`reload`/`stop`
  (`/var/run/podkop-applied`). Это устраняет ложное «не применено», когда mtime UCI новее, а конфиг
  фактически не изменился (например, после установки пакета), и наоборот — точнее показывает
  реально не применённые изменения.
- После любого успешного применения (включая procd-reload от Save & Apply) маркер обновляется,
  поэтому UI-проверка завершается успешно только когда настройки действительно применены.

## 0.9.14

### Исправлено
- **Проверка применения конфига на OpenWrt.** В OpenWrt 25.12 нет `stat`, поэтому
  `podkop get_config_status` всегда возвращал `stale: false` с нулевыми mtime. Теперь используется
  `date -r <file> +%s` с fallback на `test -nt`; предупреждение о неприменённых настройках и проверка
  после Save & Apply работают корректно.
- Проверено на роутере: при UCI новее конфига возвращается `stale: true`, после перезапуска — `false`.

## 0.9.13

### Исправлено
- **Save & Apply теперь применяется гарантированно, на уровне procd.** Служба Podkop держит
  procd-инстанс живым, а init-скрипт снова регистрирует `procd_add_reload_trigger "podkop"`.
  Любое применение `/etc/config/podkop` (LuCI, `uci apply`, `reload_config`) отправляет
  `config.change`, procd вызывает `reload`, и Podkop перезапускает sing-box с новым конфигом —
  даже если JavaScript в браузере не сработал или страница была закрыта.
- **UI проверяет результат применения:** после Save & Apply LuCI опрашивает
  `podkop get_config_status` до 20 секунд. Если procd-триггер сработал — показывается
  «Конфигурация применена». Если нет — выполняется резервный явный перезапуск с повторной
  проверкой; при неудаче выводится ошибка с командой для ручного запуска.
- Кнопка **Save** скрыта в панели действий Podkop, чтобы настройки нельзя было сохранить без
  применения; при расхождении UCI и конфига показывается предупреждение с кнопкой «Применить сейчас».

### Проверено на роутере
- `ubus call service event config.change → podkop` вызывает reload и перезапуск Podkop;
- UCI-изменения применяются, `reject`-правила блокировки появляются/исчезают вместе с секцией.
- После выключения/удаления секции Meta и применения блокировка Meta больше не остаётся в конфиге.

## 0.9.10

### Диагностика
- **DNS: показываются все серверы, а не только первый.** Раньше `check_dns_available` брал первый элемент
  списка `dns_server`/`bootstrap_dns_server`; теперь каждый сервер проверяется отдельно и выводится
  отдельной строкой со своим статусом. На тестовом роутере видны все 3 основных DNS
  (`dns.dagami.ru`, `dns.dns-ai.ru`, `77.88.8.8`) и оба bootstrap (`77.88.8.8`, `8.8.8.8` — последний
  помечается ошибкой, если недоступен).
- **Outbounds: список всех узлов секции, а не только секция.** Для selector/urltest-секций проверка
  теперь выводит каждый узел (`секция · имя узла`) с задержкой из Clash API; неответившие помечаются.
  Раньше отображалась одна строка «main [Самый быстрый]».

### Интерфейс
- **Мониторинг больше не обрезается.** Таблица получила горизонтальный скролл при нехватке ширины,
  фильтры переносятся на новую строку, на узких экранах скрываются второстепенные колонки
  (сеть/время/маршрут в зависимости от ширины), кнопки и поиск не выходят за пределы панели.
- **Единый современный дизайн всех вкладок** (Секции, Настройки, Диагностика, Дашборд, Мониторинг):
  навигация в виде «пилюль» с активным состоянием и горизонтальной прокруткой, карточки секций,
  аккуратные таблицы, единые поля ввода/кнопки, липкая панель действий внизу и адаптивные отступы
  на мобильных. Стили ограничены `#cbi-podkop`, другие страницы LuCI не затрагиваются.

## 0.9.9

## 0.9.6

### Новое
- **uTLS-маскировка TLS-отпечатка (Anti-DPI).** В настройках секции появился выбор TLS-отпечатка
  (`Chrome`, `Firefox`, `Safari macOS/iOS`, `Edge`, `Randomized`). Podkop применяет `tls.utls` ко всем
  TLS-outbound этой секции, чтобы DPI видел обычный браузерный TLS ClientHello вместо прокси-трафика.
  Опция показывается только если ядро собрано с `with_utls` (forkop — всегда).
- **Privacy & Leak Test в Диагностике (одна кнопка):**
  - **DNS Leak Test** — проверяет, что dnsmasq направляет запросы в sing-box (`127.0.0.42`,
    `noresolv=1`), что системный resolv не смотрит на провайдера и что FakeIP отвечает;
  - **Egress IP & Geo по секциям** — для каждой активной прокси-секции запрашивает внешний IP и страну
    через выбранный outbound (`sing-box tools fetch -o <tag>`);
  - **MTU / MSS** — показывает MTU WAN/LAN, наличие MSS clamp, максимальный проходящий ping-пакет
    и рекомендует MSS (`MTU - 40`).

### Исправлено
- `sing_box_get_features` добавляет `tls.utls` только при реальной поддержке ядром.
- Новые строки переведены на русский; i18n-пайплайны синхронизированы.

  неподдерживаемые настройки, а генератор конфига их пропускает. Раньше их включение давало
  невалидный JSON и Podkop не запускался.
- **`providers: []` на не-forkop ядрах.** Защита в `sing_box_cm_add_group_providers` теперь
  отсекает не только пустую строку, но и литерал `"[]"`; вызывающий код инициализирует
  теги провайдеров пустой строкой. Selector/URLTest больше не ломают `podkop-engine` и stock sing-box.
- **DNS failover на неподдерживающем ядре.** При нескольких DNS-серверах на не-forkop ядре
  используется первый сервер, а в лог пишется предупреждение вместо генерации невалидного конфига.
- **Утечка секретов в диагностике.** `show_sing_box_config` и `check_proxy` маскируют поле
  `link` parser-outbound и `providers[].url/path`.
- **Мониторинг, «Закрыть все».** Исправлен вызов несуществующего метода
  `closeAllClashApiConnections` (правильный — `closeClashApiConnections`).
- **Дашборд URL-подписок.** Сравнение типа Clash API `Selector` исправлено (было `selector`).
- **Двойной рестарт на Save & Apply.** Удалён дублирующий procd reload-trigger: остаётся один
  явный перезапуск из обработчика LuCI.
- **Drag & Drop.** При наличии штатного LuCI sortable используется он; собственная реализация
  остаётся только для старых LuCI. Двойные обработчики больше не конфликтуют.
- **Мёртвые команды.** Удалены несуществующие `main` и `check_sing_box_logs` из CLI и справки;
  добавлены рабочие `podkop enable` / `podkop disable`, а `podkop status` работает как
  псевдоним `get_status`.
- **Сообщение о версии sing-box** в диагностике использует `SB_REQUIRED_VERSION` вместо
  захардкоженного `1.12.4`.
- **`has_outbound_section`** учитывает флаг `enabled` секции.
- **TypeScript**: исправлены все ошибки `tsc --noEmit` (декларация `rpc`, типы ответов
  `MethodResponse`, `ConfigSection.label`, `getSingBoxFeatures`).

### Улучшено
- **Безопасность установщика**: убран `--no-check-certificate` (TLS проверяется всегда),
